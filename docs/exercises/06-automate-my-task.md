# แบบฝึกหัดเสริม: ออกแบบ Automation สำหรับงานของเรา

> **Optional / Take-home:** กิจกรรมเสริมหลังชั้นเรียน ไม่อยู่ในเวลาเรียนหลักและไม่เป็นเงื่อนไขการผ่านกิจกรรม Day 1

เราจะนำสิ่งที่สร้างวันนี้มาเลือกใช้กับงานจริงหนึ่งเรื่อง โดยกำหนดจุดเริ่ม ข้อมูล ขั้นตอนตัดสินใจ ผู้รับผล และวิธีวัดผลก่อนเริ่มสร้างรุ่นถัดไป

> **License:** ขั้นออกแบบไม่ต้องใช้สิทธิ์เพิ่ม สำหรับการสร้างจริงให้ตรวจ connector ทุกตัวใน Power Automate และยืนยันว่าเป็น Standard ตามสิทธิ์ขององค์กร

## Prerequisites

- เปิด [Automation Canvas](../resources/automation-canvas.md)
- เลือกงานประจำหนึ่งงานที่มีจุดเริ่มและผลลัพธ์ชัดเจน

---

## Practice 1: เลือกงานที่เหมาะกับ Automation

**Primary target:** เลือกงานหนึ่งเรื่องที่มีกติกาชัดและเกิดซ้ำ เพื่อให้เหมาะกับ flow รุ่นแรก

1. เขียนรายการงานที่ทำซ้ำ 2–3 เรื่อง
2. เลือกงานที่มีจุดเริ่มชัดเจน ข้อมูลค่อนข้างเป็นแบบแผน และผลลัพธ์ตรวจได้
3. ระบุสิ่งที่ยังต้องใช้การตัดสินใจของคน
4. จำกัดขอบเขตให้จบใน workflow เดียว

### Checkpoint

- อธิบายงานที่เลือกได้ในหนึ่งประโยค โดยมีผู้ใช้ เหตุการณ์เริ่ม และผลลัพธ์

---

## Practice 2: เติม Automation Canvas

**Primary target:** แปลงงานที่เลือกเป็น blueprint ที่ระบุ Trigger, Actions, Decision และข้อมูลที่ต้องใช้

1. คัดลอก template จาก `automation-canvas.md`
2. เติม Goal, User และ Trigger
3. เขียน input ที่จำเป็น และตัดข้อมูลที่ไม่จำเป็นออก
4. เรียง Actions จากต้นจนจบ
5. เพิ่ม Decision เฉพาะจุดที่ต้องแยกเส้นทาง
6. ระบุ Owner, ผู้รับผล และตัวชี้วัดหนึ่งค่า
7. ตรวจ connector ที่คาดว่าจะใช้ และทำเครื่องหมายรายการที่ต้องยืนยันสิทธิ์

### Checkpoint

- Canvas แสดงเส้นทางตั้งแต่ Trigger ถึงผลลัพธ์ และทุกระบบที่เกี่ยวข้องมีเจ้าของหรือข้อกำหนดสิทธิ์

---

## Practice 3: Review และวางแผนการทดสอบ

**Primary target:** ตรวจ blueprint ด้วยกรณีปกติและกรณีผิดปกติ เพื่อให้ทีมรู้ว่า flow รุ่นแรกผ่านเมื่อใด

1. อธิบาย Canvas ให้เพื่อนฟังภายใน 2 นาที
2. ให้เพื่อนถาม 3 ข้อ หรือใช้คำถามเหล่านี้ตรวจงานด้วยตนเองเมื่อทำเป็น Take-home:

   - Trigger เกิดขึ้นจริงเมื่อใด?
   - ถ้าข้อมูลไม่ครบหรือ action ล้มเหลวจะเกิดอะไรขึ้น?
   - เราจะรู้ได้อย่างไรว่า automation ช่วยงานได้จริง?

3. เขียน test case อย่างน้อย 3 กรณี: เส้นทางปกติ, เส้นทางทางเลือก และ failure
4. ระบุข้อมูลฝึกที่ไม่เป็นความลับและผู้รับทดสอบ
5. ปรับ Canvas รอบสุดท้าย

### Checkpoint

- มี test case 3 กรณี พร้อมผลที่คาดหวังและผู้ตรวจผล

> **💡 Tip:** เริ่มจาก flow รุ่นเล็กที่คนตรวจได้ เหมือนทดลองสูตรกับจานเล็กก่อนทำทั้งครัว
